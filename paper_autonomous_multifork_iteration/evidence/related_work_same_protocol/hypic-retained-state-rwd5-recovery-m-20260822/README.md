# RW-D5 operational recovery M

M supersedes L before GPU submission. L correctly froze the exact three-file
chmod-only model-view repair, but its final ordinary `exec env` could inherit
ambient K overrides such as `CODE_DIR` or `PYTHON_BIN`. That could verify the K
manifest and then execute non-K code. L is retired and supplies no execution.

M preserves the same completed asset repair and unchanged K science. Its
preflight uses pinned command paths, verifies both exact manifests and every
post-repair file stat/hash, requires zero writable top-level model files and
fresh M paths, and copies the frozen repair receipt. It then executes
`/usr/bin/env -i` with a closed environment: every K-overridable code, freeze,
live-debug, Python, official-repository, model-ledger, data, run, and
instrumented-repository input is an explicit absolute K/M value. The K launcher
is invoked by exact absolute path with `--noprofile --norc`.

`test_recovery_m_env.py` parses the actual final exec block and injects
malicious ambient values for all critical variables plus `BASH_ENV`. The
observed child environment contains only the frozen whitelist, with every
attacker value absent or replaced.

M is operational authority, not a new science freeze and not a result. Fresh
independent GREEN is required before it may launch K's 16 affected cells.
