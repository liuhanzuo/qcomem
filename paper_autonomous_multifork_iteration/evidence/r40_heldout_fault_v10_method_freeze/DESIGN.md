# V10 authority and lifecycle design

The signed binding commits the canonical archive and source ledger; snapshot and inventory; runner manifest and inventory; runtime expectation; typed execution contract; positive attempt; unique run nonce; and canonical path/device/inode identity of both the terminal root and independent consumption root. Full byte, schema, member-closure, path, and signature preflight occurs before any process API is reached.

Authority is function-local and consume-once. With SIGINT/SIGTERM blocked, the launcher rechecks both directory objects, hashes the canonical root-object/nonce/attempt run identity, atomically publishes a no-replace record under that hash in the durable root, and publishes the same bytes as `AUTHORIZED_CONSUMPTION.json` in the terminal root. The signed binding hash is evidence inside the record but is deliberately not its uniqueness key, so a re-signed binding cannot replay the same run identity. Only then does the fixed signed provenance probe run. Thus a probe failure still consumes authority and closes to failure terminals; a replay after terminal clearing reaches the retained durable record before any process creation.

Immediately before every worker, the binding, expectation, contract, runner, archive, ledger, and derived eight-spec aggregate are re-read and reverified. The runtime schema requires argv[0] to be the directly loaded Python image, not a launcher that later execs another image. The only worker Popen site launches that signed image and bootstrap with a canonical payload. Signals remain blocked until the returned process is stored, PID/PGID are registered, and the child's canonical report has been checked. The report measures the effective loaded Python vnode rather than trusting a post-Popen lookup of argv[0], and binds exact logical argv, typed argv, cwd object, allowlisted environment, CUDA visibility/physical UUID, PID, PGID, and actual-spec digest.

Finalization terminates owned process groups when needed, waits for confirmed death, rehashes inputs, verifies both consumption copies, and recomputes the typed actual-spec aggregate from the eight child receipts. Success requires that aggregate to equal the pre-authorized signed aggregate and requires eight zero exits. Failure paths preserve typed null/unverified states rather than fabricating actual measurements. Publication is transactional and no-replace: eight `V10F01`--`V10F08` terminal records are published together, alongside the already existing local consumption record, and the validator rejects missing or extra names.
