# A8 — Reconciling the two Store estimands

## A8.0 Headline

**The two estimands are numerically identical on the eight shared items. The
residual unexplained difference is exactly zero bytes for every matched row.**
The 136.235-versus-140.34 gap is not an accounting gap at all: it is entirely a
*cohort-and-statistic* gap. Table 1 reports a **mean over 60 items**; Table 2
reports a **median over the 8-item subset**, which contains systematically
longer documents. Once cohort and statistic are held fixed, the component sum
and the entry-owned byte-range union agree to the byte.

## A8.1 Data and method

Component estimand (Table 1): `stored_persistent_nbytes` in
`evidence/qcomem_mixed_validation_60item_20260812d/artifacts/raw/`
(48 shards; 60 items x 6 configurations; each row carries `dataset` and
`source_index`). Its own replay verifier
(`.../replay/verify.py:304-309`) enforces

## A8.2 A closed form for the component accountant, verified exactly

To compare configurations that exist in only one of the two runs (uniform Q8
and uniform Q4 appear in Table 2 but not in the 60-item panel), I recovered the
accountant's closed form from the archived shards and then verified it against
every archived value.

Let `T` be `document_tokens` and `pack(n,b) = ceil(n/64) * (8b + 4)` for `b<16`,
`pack(n,16) = 2n`. Then

- boundary residual: `pack(2048*T, b_res)` — hidden size 2048, so residual
  elements are exactly `2048*T` (this identity holds for all 60 items against
  the archived `residual_error_sums.elements`);
- one full-attention layer sits at lower index 3, holding `1024*T` KV elements
  (2 x 4 KV heads x 128 head dim), contributing `pack(1024*T, b_3)`;
- the other six lower layers are GDN, each holding `524288` recurrent elements
  plus `32768` convolution elements. At Q16 the layer costs
  `524288*4 + 32768*2 = 2,162,688` bytes (**recurrent state is FP32, conv is
  BF16**); at width `b` it costs `pack(557056, b)`;
- full-prefix Q16 keeps all 40 layers: `10 * 1024*T * 2 + 30 * 2,162,688`.

**Verification: 780 exact byte identities checked across the 60 items and five
retained configurations; 0 mismatches.** (960 including the residual-element
identities.) No fitted constants, no tolerances.

Worked example, qasper index 6, `T = 3997`, frozen Q4/Q4/Q8:

```
residual  : pack(2048*3997, 4)  = ceil(8,185,856/64)*36 = 127,904*36 = 4,604,544 B
lower attn: pack(1024*3997, 4)  = ceil(4,092,928/64)*36 =  63,952*36 = 2,302,272 B
lower GDN : 6 * pack(557056, 8) = 6 * (8704*68)         = 6*591,872  = 3,551,232 B
component sum                                            = 10,458,048 B = 9.9736 MiB
archived stored_persistent_nbytes                        = 10,458,048 B   [exact]
```

### Decomposition of the published gap

Because Store is affine in document tokens (`slope * T + const`), the gap
decomposes in closed form as `slope * delta(document tokens)`:

| row | Table 1 -> Table 2 total | (a) cohort composition, mean60 -> mean8 | (b) statistic, mean8 -> median8 | (c) **estimand**, component -> byte-range |
|---|---|---|---|---|
| Full-prefix Q16 | **+4.1064 MiB (+3.01%)** | +2.8442 MiB (69.3%) | +1.2622 MiB (30.7%) | **+0.0000 MiB (0.0%)** |
| Q-CoMem Q8 | +0.6545 | +0.4533 | +0.2012 | **0.0000** |
| frozen Q4/Q4/Q8 | **+0.3465 MiB (+3.59%)** | +0.2400 (69.3%) | +0.1065 (30.7%) | **0.0000** |
| same-memory / per-layer | +0.3465 | +0.2400 | +0.1065 | **0.0000** |

Check: full-prefix slope is 20,480 B/token, so (a) = 20,480 x (3952.875 -
3807.25) = 2,982,570 B = 2.8442 MiB and (b) = 20,480 x (4017.5 - 3952.875) =
1,323,520 B = 1.2622 MiB. For every Q4-residual policy the slope is 1,728
B/token, so (a) and (b) are identically +0.2400 and +0.1065 MiB — which is why
the frozen and same-memory rows show the *same absolute* offset.

**The mechanism is one short document.** qasper index 6-9 happens to include the
only truncated-short document in the subset (3448 tokens against 3997-4050 for
the other seven). It drags the 8-item *mean* down but not the *median*, which is
term (b); and the subset as a whole is 3.83% longer than the 60-item cohort,
which is term (a).

## A8.4 What I cannot decompose from archived data alone

Stated plainly, three things are not settled by this analysis:

1. **Per-item byte-range values do not exist in the archive.**
   `evidence/h20_deployment_benchmark/summary.json` publishes only medians for
   the six in-process rows (plus one exact byte value,
   `comem_q8_median_payload_bytes = 16,664,352`). The identity is therefore
   established *at the median*, at five design points, not item by item. Eight
   per-item byte-range values are archived for HYPIC but not for Q-CoMem.

2. **The byte-range accountant's source is not registered.**
   `evidence/method_provenance.tsv` has `M-R34-HYPIC-STORE-RECEIPT` for the
   SGLang receipt overlay and `M-H20-DEPLOYMENT-DERIVATION` for the table
   generator (which only *reads* the frozen summary), but **no row for the
   in-process Q-CoMem byte-range accountant**. Restoring it is A11's job.
   Without it I can prove the four terms *sum* to zero but cannot prove each is
   individually zero; two cancelling non-zero terms are not formally excluded,
   though exact cancellation at five independent design points spanning a 17x
   range is not a credible reading.

3. **I cannot distinguish "definitionally identical" from "same code".**
   Two readings survive: (i) the byte-range union of a contiguous, non-aliased,
   un-padded packed entry *is* the component sum, so the two implementations
   necessarily agree on Q-CoMem entries; or (ii) the eight-item execution reused
   the component accountant and Table 2's footnote describes it imprecisely.
   Reading (i) is the one I recommend the paper assert, because it is a
   provable property of the storage layout rather than a claim about which
   function ran — but it is a claim the paper must support by publishing the
   accountant, not by citing this reconciliation.

## A8.5 Correction to A1 (important)

A1 concluded that the lower-cache counter is defective because it "omits the 4
bytes per group of BF16 scale and bias", and that the published 14.10x is
therefore wrong. **The archived data does not support that mechanism, and I
recommend A1 be revised.**

- A1's hypothesised counter (metadata omitted, GDN reference in BF16) **fails
  240/240 lower-cache values** — it is not merely unlikely, it reproduces none
  of them.
- The metadata **is** included: the attention layer costs exactly 576 B/token at
  Q4 (= 36/64 x 1024 elements/token) and 320 B/token at Q2 (= 20/64 x 1024), and
  each GDN layer costs exactly `557056 * 68/64 = 591,872` B at Q8. These are the
  *with-metadata* rates, verified on all 60 items.
- A1's real observation — that frozen lower-cache compression is **3.6164x**,
  above the 3.5556x Q4 ceiling — is reproduced exactly by my model, and is
  explained without any counter defect: **the Q16 reference stores the GDN
  recurrent state in FP32, not BF16.** The attention part compresses at exactly
  the Q4 ceiling (2 / 0.5625 = 3.5556x); the GDN part compresses at
  2,162,688 / 591,872 = **3.6540x** because its reference is 4 bytes/element for
  524,288 of its 557,056 elements. The observed 3.6164x lies strictly between
  the two, as it must. There is no impossibility.

**Consequence for the headline.** 14.10x is arithmetically correct against the
denominator the paper actually uses, and A1's proposed 13.2-13.6x correction
should be withdrawn. But a different, real caveat replaces it: at the 60-item
mean, the full-prefix Q16 baseline of 136.235 MiB/doc is

| baseline component | bytes at median doc | share |
|---|---|---|
| 10 attention layers, BF16 KV | 82,278,400 | 55.9% |
| 30 GDN layers, recurrent state **FP32** | 62,914,560 | 42.8% |
| 30 GDN layers, conv state BF16 | 1,966,080 | 1.3% |

so **42.8% of the "Q16/BF16" reference is FP32**. Against an all-BF16 reference
(106.235 MiB/doc at the 60-item mean) the frozen policy compresses **10.996x**,
not 14.102x. The paper should either (a) keep 14.10x and state in the Table 1
footnote that the reference retains GDN recurrent state in FP32 as the stack
produces it, which is the deployed baseline, or (b) report both. I recommend
(a) plus the footnote: the FP32 recurrent state is what the unmodified stack
actually holds, so it is the honest deployed denominator — but a reader
comparing against a BF16-everywhere system must be told.

## A8.6 The cross-runtime HYPIC ratios (R44-4-09)

`Sec. G.1` divides across runtimes: "Prefix Cache and HYPIC retain 8.78x and
20.39x as much Store as CoMem Q8". Two facts from the archive:

**Against the ratio.** The HYPIC/Prefix denominators are page-quantized and the
Q-CoMem denominator is element-exact. Across eight documents whose lengths
differ by up to 549 tokens, the SGLang Prefix Cache payload takes only **3
distinct values** (145,653,760 / 146,964,480 / 133,857,280) with all pairwise
gaps integer multiples of **1,310,720 B** (= a 128-token page across ten
attention layers); the Q-CoMem full-prefix payload takes **8 distinct values**,
one per document, varying continuously at 20,480 B/token. Per token per
attention layer the two accountants also differ by exactly 2x (10,240 versus
20,480 B/token across the ten layers), which the archive does not explain. These
are not identical inclusion rules, and the paper's own Table 18 caption already
says timing is compared only within blocks.

**For a bounded equivalence statement.** The two stacks' *nominally same object*
— the retained full prefix for the same checkpoint, slice and token cap — reads
139.53 MiB (SGLang receipts) versus 140.34 MiB (in-process), a **0.58%**
difference. That bounds the cross-runtime inclusion-rule discrepancy at the one
design point where both stacks hold the same thing.

**Recommendation.** Do not print 8.78x / 20.39x. Replace with the three values
side by side plus the calibration sentence, e.g.:

> Under the separate byte-range-union estimand, CoMem Q8 retains 15.89
> MiB/document, SGLang Prefix Cache 139.53 MiB, and HYPIC 324.09 MiB. The two
> stacks' full-prefix arms — the one object both hold — differ by 0.58%
> (140.34 versus 139.53 MiB), so the retained-state levels are broadly
> commensurable; but the SGLang payload is quantized to 128-token pages while
> the in-process payload is element-exact, so we report the levels rather than
> their ratio.

If the ratio is retained, it must carry that quantization caveat and be labelled
cross-runtime in the sentence itself, not only in the table caption.

## A8.7 Which estimand should be canonical

**Canonical: the entry-owned physical byte-range union.** Reasons:

1. It is the quantity a deployment engineer can act on — bytes the allocator
   cannot reclaim while the entry is retained.
2. It is already the paper's own formal object: Appendix D defines the
   conservative half-open byte interval `I = [em, e(M+1))` from
   shape/stride/offset and the storage-ID-normalized union over rows. Making
   Store use the same definition as the ownership witness removes one
   definition from the paper.
3. It is what the external HYPIC receipts measure, so it is the only estimand
   under which any cross-system statement can even be attempted.
4. **It costs nothing:** as shown above, it equals the component sum exactly for
   Q-CoMem entries, so no published number changes.

The component sum is then demoted from a second estimand to a *decomposition* of
the canonical one: it is how the canonical figure is broken into residual data,
scales/biases, and lower-cache storage. Sec. 5.1's "the accounting
implementations differ" should become "the 60-item panel reports the same
byte-range union broken into its stored components; on the eight shared items
the two implementations agree exactly."

**The real annotation burden moves to cohort and statistic**, which is where the
3% actually lives.
